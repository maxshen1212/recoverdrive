# RecoverDrive Phase 5 (E4 latency, E5 ablation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (native, inline; autonomous-run skill).

**Goal:** Measure where the time goes (E4), test the "call the VLM only when checks are suspicious" optimization, and run the
spec §5.3 ablations (E5); then write a comprehensive REPORT.md covering Phases 1–5.

**Architecture:** Ablations change exactly one component of Ours, everything else frozen (commit 5d5283c settings).
Recovery-logic ablations and the VLM gate are *replayed offline* from the logged VLM answers of the frozen test run
(deterministic and exact; no GPU). Component ablations that change VLM inputs or the model (no checks, Qwen grounding,
4B, Thinking) are new runs of Ours (ours_detect + ours_full) on the test split.

**Spec:** `docs/superpowers/specs/2026-11-03-recoverdrive-design.md` (§4.2, §4.3, §5.3, §5.4, §6 Phase 5)

## Global Constraints
- Frozen settings from commit 5d5283c (thresholds, prompts, recovery, shield). Ablation switches default to off and must
  reproduce Ours-full exactly when off.
- Dev split for developing/smoke-testing a variant; the test split for the reported number, run once per variant, 3 seeds
  where affordable (spec §5.4: report test numbers; stochastic settings 3 seeds, mean ± std).
- GPUs are shared: check `nvidia-smi` before every launch; keep ≥ 4 GB free on any card we use; vLLM at
  `VLM_GPU_UTIL` ≤ 0.5. New model weights go to a Hugging Face cache on the data disk (`HF_HOME`), because the root disk is 96 % full.
- Never add vllm to the root project; never edit the spec; no push.

## Review Focus
1. Replay must reproduce the logged Ours-full state/action on every test frame before any replayed variant is trusted
   (`scripts/replay_ablation.py --check`).
2. A variant that silently changes Ours-full (default switches) would corrupt the main result: the full unit suite must
   pass unchanged, and replay-with-defaults must match 100 %.
3. Qwen grounding returns 0-1000 relative boxes; a wrong scale would make every match rate 0 (check on dev clean frames).
4. The Thinking model emits reasoning before JSON; with schema-constrained output the reasoning must be parsed out
   (vLLM `--reasoning-parser`), else every answer is invalid (smoke on dev before test).
5. E4 timings are meaningless with a cache or a busy server: fresh cache file, workers 1, methods sequential, dedicated
   vLLM server.

## Decisions taken as defaults
- **DEFAULT (E1)** Ablations are reported on the test split with the frozen settings; nothing is tuned on test.
- **DEFAULT (E2)** 32B is not run: bf16 needs ~64 GB (two shared GPUs); spec marks it "if time allows".
- **DEFAULT (E3)** LoRA (bonus) and adjacent-camera re-observation (§4.3 "later") are not done.
- **DEFAULT (E4)** Ablations apply to Ours only; baselines are unchanged.
- **DEFAULT (E5)** −isolation: no sensor or agent isolation; any confirmed fault is unresolved (stop). −re-observation:
  no memory across frames (no persistence promotion, no carried isolation). −sampling: final answer = last valid attempt.
- **DEFAULT (E6)** VLM gate "flags": the VLM is called only when a deterministic flag is raised; otherwise the frame is
  healthy without a call (agent faults then cannot surface).
